# سياسة المزامنة التلقائية مع GitHub

## السياسة المعتمدة

بناءً على طلب مالك المشروع، يُدفع كل **التزام جديد** على الفرع `main` تلقائياً إلى البعيد `github/main`. يُنفذ ذلك بخطاف Git محلي محفوظ في `.githooks/post-commit` ويُفعّل في النسخة العاملة عبر `scripts/install-github-autosync.mjs`.

لا ينشئ الخطاف التزامات من تلقاء نفسه؛ فكل تعديل مكتمل يلتزم به مسار التطوير أولاً، ثم يدفعه الخطاف فوراً. تمنع هذه الآلية إرسال ملف نصف مكتمل بينما تحقق الدفع الفوري بعد كل تعديل معتمد.

## التحقق والاسترداد

بعد كل التزام، يعرض الخطاف نتيجة الدفع. إذا أخفق الاتصال أو انتهت مصادقة GitHub، يبقى الالتزام محفوظاً محلياً ولا يُفقد أي تغيير؛ تكفي إعادة تنفيذ `git push github main` بعد إصلاح المصادقة. لا يعمل الخطاف على أي فرع غير `main` ولا ينفذ دفعاً عودياً متكرراً.

## إعادة التفعيل في نسخة عمل جديدة

بعد استنساخ المستودع أو فتحه في بيئة جديدة، شغّل الأمر التالي مرة واحدة من جذر المشروع:

```bash
node scripts/install-github-autosync.mjs
```

يتطلب التشغيل صلاحية دفع صالحة إلى مستودع GitHub المحدد. تحفظ نقطة إصدار قبل أي تعديل كبير حتى يبقى الاسترداد متاحاً من سجل الإصدارات.

## قابلية نقل السياسة

تُحفظ السياسة الملزمة لعمليات التطوير في ملف `AGENTS.md` داخل المستودع، لذلك تنتقل مع الشيفرة إلى كل بيئة عمل. أما قيمة Git المحلية `core.hooksPath` فلا تُخزن في Git بطبيعتها؛ لهذا يلزم تشغيل سكربت التفعيل مرة واحدة لكل نسخة عمل جديدة. لا يبدأ التطوير في بيئة جديدة قبل تنفيذ هذا التفعيل والتحقق من مخرجه.
