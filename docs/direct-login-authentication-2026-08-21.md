# تدفق الدخول المباشر

**التاريخ:** 21 أغسطس 2026  
**النطاق:** مصادقة Firebase بالبريد/كلمة المرور أو Google داخل «ديوني وميزانيتي برو».

## القرار

أزيلت ميزة **إلزام تأكيد البريد الإلكتروني** من التطبيق. بعد نجاح Firebase Auth، يرسل نموذج الدخول النتيجة إلى مستمع الجلسة المركزي، الذي يهيّئ ملف المستخدم وبياناته المالية. لا يتحقق التطبيق من الحقل `emailVerified`، ولا يرسل رسائل تأكيد، ولا يعرض صفحة إعادة إرسال أو صفحة نجاح لتأكيد البريد.

## النتيجة المتوقعة

| الحالة | السلوك |
|---|---|
| حساب قائم غير مؤكد البريد | يدخل مباشرة بعد صحة بيانات الدخول، ثم تُحمّل بياناته ضمن مهلات الاستعادة الحالية. |
| حساب جديد بالبريد وكلمة المرور | يُنشأ ملفه المالي ثم ينتقل مباشرة إلى التطبيق، بلا إرسال بريد أو تسجيل خروج تلقائي. |
| تسجيل Google | يستمر بتمرير النتيجة إلى مستمع الجلسة المركزي فقط. |
| تعذّر جلب ملف المستخدم أو السجلات | تبقى مهلات التحميل ورسالة الاستعادة الآمنة فعّالة؛ لا توجد شاشة معلّقة متعلقة بالبريد. |

## الضوابط التي بقيت فعّالة

إلغاء تأكيد البريد **لا يلغي المصادقة أو عزل البيانات**. ما زالت كل قراءة وكتابة مالية تستخدم هوية Firebase المصادق عليها، وتستمر قواعد Firestore المقيدة بمالك المسار، وتجديد رمز الهوية قبل القراءة الأولى، ومنسق التحميل الذي يمنع نتائج الجلسة القديمة من الكتابة فوق جلسة أحدث.

## التحقق التقني

يغطي عقد تدفق الدخول عدم وجود استدعاء `sendEmailVerification` أو حارس `emailVerified`، واستمرار استخدام `onIdTokenChanged` لتشغيل تحميل بيانات الجلسة. تُشغّل اختبارات الوحدة وفحص TypeScript والبناء الإنتاجي قبل اعتماد الإصدار.
