# سجل التدقيق الأمني — 20 أغسطس 2026

## الملخص التنفيذي

يغطي هذا التدقيق واجهة التطبيق وخادم Express، والمصادقة والتخويل، وعزل بيانات Firebase/Firestore/Storage، ومسارات المرفقات، والإعدادات وملفات النشر، واعتمادات الإنتاج. أُغلق المسار الأخطر المكتشف في وسيط تخزين Forge: لم يعد أي طلب إلى `/manus-storage/*` ينتج رابط تنزيل موقّعاً، بل يعيد استجابة `404` متعمدة. تعتمد المرفقات المالية الآن على مسار التطبيق المحمي الذي يتحقق من هوية Firebase وملكية السجل قبل استرجاع أي محتوى.

> **حالة الإصدار قبل الحفظ:** لا يعرض `pnpm audit --prod` أي ثغرات معروفة، واجتازت حزمة الاختبارات **77 اختباراً في 24 ملفاً**، كما اكتمل فحص TypeScript وبناء Vercel بنجاح.

## النطاق والمنهجية

شملت المراجعة قراءة مسارات الخادم ونقاط الدخول، والتحقق من تدفقات رفع/معاينة المرفقات، ومراجعة قواعد Firebase Storage المنشورة، وفحص الاعتمادات الإنتاجية قبل وبعد المعالجة. كما تمت مراجعة السجل التشغيلي والتوثيق لإزالة بيانات QA وروابط الوصول المؤقتة التي لا ينبغي الاحتفاظ بها.

| مجال المراجعة | عناصر التحقق | النتيجة |
|---|---|---|
| المصادقة والتخويل | Firebase ID Token وملكية السجل والمساعدين المخولين | المسارات المالية والمرفقات تتحقق من المالك قبل القراءة أو التعديل |
| التخزين | Firebase Storage ووسيط Forge القديم | أُغلق المسار العام القديم؛ المرفقات المحمية لا تستخدم رابطاً عاماً |
| إدخال الملفات | نوع MIME وBase64 والحجم والمحتوى | يُرفض المحتوى غير القانوني أو غير المطابق لنوع الملف المعلن |
| الخادم | الرؤوس وحدود جسم الطلب | أُضيفت رؤوس حماية وحدود أصغر ومتناسبة مع المرفقات |
| الاعتمادات | تدقيق إنتاجي بعد التحديث | لا توجد ثغرات إنتاجية معروفة وفق أداة الفحص |

## تغييرات الاعتمادات

لم يُستخدم `streamdown` في الشيفرة؛ أُزيل بدلاً من إبقاء سلسلة Mermaid وDOMPurify غير المباشرة. كما رُقيت الحزم المباشرة والطبقات التشغيلية إلى إصدارات مصححة ومتوافقة مع الاختبارات.

| الحزمة أو المسار | قبل | بعد |
|---|---:|---:|
| `axios` | 1.12.2 | 1.19.0 |
| `streamdown` وMermaid/DOMPurify التابعة له | 1.4.0 / غير مباشر | أزيلت من المشروع |
| AWS S3 SDK | 3.907.0 | 3.1114.0 |
| Express | 4.21.2 | 5.2.1 |
| tRPC | 11.6.0 | 11.18.0 |
| Drizzle ORM | 0.44.6 | 0.45.2 |
| Nanoid | 5.1.6 | 5.1.16 |
| Recharts | 2.15.4 | 3.10.1 |

أُضيف ملف `pnpm-workspace.yaml` لتثبيت سياسة موحدة للاعتمادات غير المباشرة وللحفاظ على تصحيح Wouter المحلي المستخدم في بيئة المشروع.

## ضوابط المرفقات وعزل البيانات

تظل قاعدة Firebase Storage مقيدة بمسار `financial-attachments/{userId}/...` ولا تمنح القراءة أو الكتابة إلا إذا طابق `request.auth.uid` صاحب المسار. وعلى الخادم، لا تكفي معرفة معرف المرفق أو السجل: تمر المعاينة والتنزيل المحمي عبر تحقق رمز Firebase ثم تحقق ثانٍ من ملكية السجل قبل إعادة المحتوى، مع استجابات خاصة لا تُخزَّن مؤقتاً.

أضيفت قيود للملاحظات الداخلية للمرفقات، فتُرفض الملاحظات غير النصية أو الأطول من 2,000 حرف أو التي تتضمن محارف تحكم غير مسموحة. وتبقى الملاحظات معروضة كنص React مُشفّر افتراضياً، وليس كـ HTML منفذ.

## قيود ونقاط متابعة

التعطيل الحالي لمسار `/manus-storage/*` مقصود؛ لا ينبغي إعادة تفعيله إلا مع عقد ملكية صريح لكل نوع ملف واختبارات تخويل مقابلة. كما أن سياسة أمن المحتوى (CSP) غير مفروضة في هذه النسخة؛ يلزم حصر نطاقات Firebase والخدمات الخارجية المستخدمة في الإنتاج واختبارها أولاً حتى لا يمنع المتصفح المصادقة أو المعاينة الشرعية. توصي المراجعة أيضاً بتفعيل حدّ معدّل للطلبات على مستوى Vercel أو بوابة الحماية قبل تعريض نقاط الرفع أو المصادقة لحمل عام مرتفع.

لا يغني هذا السجل عن المراقبة الدورية: يُعاد تشغيل فحص الاعتمادات مع كل تحديث، وتُراجع قواعد Firebase عند إضافة أي مسار تخزين جديد أو أي دور فريق جديد.
