# التحقق المستمر وصحة النشر عبر Vercel

**التاريخ:** 22 أغسطس 2026  
**النطاق:** مستودع `hasaniraq66/moh` ومشروع Vercel `moh`.

## التصميم المعتمد

يستخدم المشروع **ربط Git الأصلي في Vercel** للنشر التلقائي من فرع `main`. لذلك لا ينفذ GitHub Actions أمراً ثانياً للنشر ولا يحتاج إلى مفاتيح Vercel داخل أسرار GitHub. هذا يمنع تكرار عمليات النشر ويحافظ على مصدر نشر واحد.

يعيد سير العمل `Security, quality, and deployment health` تشغيل فحوصات الجودة لكل طلب دمج ولكل دفع إلى `main`، ثم ينفذ تحققاً مستقلاً من صحة الإنتاج عند الدفع إلى `main` فقط.

| المرحلة | الإجراء |
|---|---|
| إعداد الحزمة | `pnpm/action-setup@v4` يعتمد نسخة `pnpm` المعلنة في حقل `packageManager` داخل `package.json`، من دون تعريف نسخة ثانية متعارضة. |
| التحقق | تثبيت مقفل، اختبارات الوحدة، فحص TypeScript، بناء Vercel، وتدقيق اعتمادات الإنتاج. |
| صحة النشر | بعد نجاح الفحوصات، ينتظر السَّير حتى ست دقائق استجابة HTTP ناجحة (`2xx` أو `3xx`) من نطاق إنتاج Vercel. |

## نتيجة التحقق

التشغيل [32555109741](https://github.com/hasaniraq66/moh/actions/runs/32555109741) للالتزام `77ef53f` اكتمل بنجاح. نجحت وظيفتا **Verify application and production dependencies** و**Confirm Vercel production health**. كما سجّل Vercel نشر إنتاج بحالة `READY` للالتزام نفسه.

> لا يثبت فحص الصحة صحة كل ميزة وظيفية؛ بل يثبت أن نشر الإنتاج أصبح قابلاً للوصول بعد اجتياز فحوصات المشروع. تظل اختبارات المستخدم الأساسية والتحقق من السجلات التشغيلية جزءاً من المتابعة الدورية.
