# ملاحظات توافق Vercel

## سبب العطل المرجح

تتوقع بنية المشروع الحالية خادماً Express طويل التشغيل ليخدم واجهة Vite من `dist/public` ويعالج المسارات الخلفية. لا يضمن Vercel تشغيل هذا المسار كما هو أو استخدام `express.static()` لخدمة الأصول؛ إذ تعتمد المنصة الأصول الموجودة في مخرج ثابت ودوالاً خادمية مصدّرة.[1]

## قواعد التكييف

تتطلب واجهة Vite في وضع SPA إعادة كتابة للمسارات العميقة إلى `index.html`، مع استثناء مسارات `/api` لتصل إلى الدالة الخادمية.[2] يجب تصدير تطبيق Express كدالة افتراضية من نقطة دخول خادمية وعدم استدعاء `listen()` في بيئة Vercel.[1]

| الموضوع | الإعداد المطلوب |
| --- | --- |
| الواجهة | أمر بناء Vite ينتج الأصول في مجلد ثابت مخصص لـVercel. |
| الخادم | نقطة دخول داخل `api/` تصدر تطبيق Express من دون خادم دائم. |
| التوجيه | إعادة كتابة `/api/*` إلى الدالة ثم إعادة كتابة بقية المسارات إلى `index.html`. |
| المتغيرات | إضافة متغيرات Firebase والتهيئة الخلفية الضرورية ضمن إعدادات Vercel وعدم حفظ قيمها في Git. |

## ملاحظة تكييف الخادم

توضح وثائق Vercel أن تطبيق Express يمكن أن يعمل كدالة واحدة عندما يُصدّر التطبيق، وأن الأصول الثابتة يجب أن تُخدم من مخرج البناء بدلاً من `express.static()`.[1] لذلك سيُفصل إنشاء تطبيق Express عن استدعاء `listen()` المحلي، وسيُستخدم مدخل خادمي متوافق مع Vercel ليصل كل من `/api/trpc` ومسارات المرفقات والمستشار المالي إلى التطبيق نفسه.[3]

## الإعداد المنفذ

أضيف ملف `vercel.json` الذي يشغّل `pnpm run build:vercel` ويقدّم محتوى `dist/public` الثابت. تُعاد كتابة `/api/*` أولاً إلى دالة `api/index.ts`، وتُعاد كتابة بقية المسارات إلى `index.html`، وبذلك لا تُرسل صفحة React العميقة إلى دالة API. يعيد مدخل API مسار `/api/*` الأصلي إلى تطبيق Express المشترك قبل تمريره إليه.

| الإعداد في Vercel | القيمة |
| --- | --- |
| إطار العمل | **Other** أو إعداد مخصص؛ لأن التطبيق يجمع Vite وExpress. |
| أمر التثبيت | `pnpm install --frozen-lockfile` |
| أمر البناء | `pnpm run build:vercel` |
| مخرج الواجهة | `dist/public` |
| نقطة API | `api/index.ts` |

## متغيرات البيئة والحدود

أضف في مشروع Vercel، لكل من Production وPreview عند الحاجة، المتغيرات الخادمية التي يستخدمها التطبيق: `JWT_SECRET` و`DATABASE_URL` و`OAUTH_SERVER_URL` و`VITE_APP_ID` و`OWNER_OPEN_ID` و`BUILT_IN_FORGE_API_URL` و`BUILT_IN_FORGE_API_KEY`. لا تحفظ قيماً في Git ولا تضع المفاتيح ضمن متغيرات تبدأ بـ`VITE_` إلا إذا كان من الآمن كشفها للمتصفح.

> تعتمد معاينة المرفقات ورفعها والمستشار الذكي حالياً على متغيري `BUILT_IN_FORGE_API_URL` و`BUILT_IN_FORGE_API_KEY` الصادرين من بيئة Manus. لا تنتقل هذه الاعتمادات تلقائياً إلى Vercel. إن لم تتوفر بيانات اعتماد صالحة ومصرح بها في Vercel، ستظهر الواجهة لكن ستحتاج هذه الميزات إلى مزود تخزين ومزود نموذج لغوي مستقلين قبل أن تعمل هناك.

## خطوات النشر

اربط مستودع GitHub الحالي في Vercel، واترك Vercel يقرأ `vercel.json` من جذر المستودع، ثم أضف المتغيرات السابقة من صفحة **Settings → Environment Variables**. بعد النشر، اختبر الصفحة الرئيسية ومسار عميق مثل `/debts`، ثم سجّل الدخول واختبر `/api/trpc` ورفع مرفق. لا تنفّذ نشر إنتاجي قبل إدخال المتغيرات السرية المطلوبة.
